## 해결로 인정된 것
- 교차 청구 탐지: 같은 편 다른 청구인이 서류를 재사용하면 탐지하고, 먼저 올린 청구는 서류를 유지한다.
- 미해결 확인 사항을 한 목록으로 통일했다. 목록 배지, 체크리스트, 승인 사유 요청이 모두 같은 목록을 쓴다.
- 제출 후 지급 안내를 고정 줄로 표시하고, 예상 청구액과 입금 계좌를 보여 준다.
- 보험사 브랜딩(문자, 헤더, 보안 페이지)과 TD-6 자동 연장 답변을 넣었다. 강민준 사례에서 "따로 연장하지 않아도 된다"를 근거와 함께 답한다.
- 모델 장애 시 대체 답변을 보낸다. "답변 작성 중"이 계속 떠 있지 않는다.

## 새로 드러난 문제
### P0 (반영함)
- **영어 화면이 멈춤:** 영어 문구 객체에서 `estKrw` 뒤의 주석이 같은 줄에 있던 `estDetail`까지 주석으로 만들었다. 그래서 영수증이 잡힌 영어 사용자는 `refresh()`에서 예외가 나고, 이후 새 메시지가 그려지지 않았다. v3 반영 작업에서 생긴 회귀다.
  - 수정: 키를 별도 줄로 분리했다.
  - `drawChecklist()`를 try/catch로 감쌌다. 시트 그리기가 실패해도 대화는 계속 그려진다.
  - en/ko 키 일치 테스트를 추가했다. node로 실제 객체를 평가하며, 이번 회귀를 되살리면 이 테스트가 실패하는 것을 확인했다.

### 빨리 고칠 것 (문구와 표시)
1. 단정 표현이 남아 있다. agent.md의 예시 "보상될 가능성이 높아요"와 대시보드 판단 본문의 "보상 가능성 높음"이다.
2. 교차 청구를 여행자에게 안내하는 문구가 탐지 사실을 드러낸다. 중립적인 "본인 명의 서류로 다시" 형태로 바꿔야 한다.
3. 웹 채팅에 문자용 문구가 남아 있다. 웹 사용자에게 "or reply SUBMIT"이 보이고, 규칙 기반 제출 문구에 `[CL-4]` 코드가 노출된다. 패킷의 조항 표에는 `;`가 남아 있다.
4. 패킷에 "원래 항공권은 항공사 확인서로 인정함"이라는 근거가 없다.
5. 고정 줄의 "3영업일 안에 지급"에 조건이 빠져 있다. "서류를 모두 받은 날부터"를 붙이고 실제 날짜로 보여 줘야 한다.
6. 진행 과정이 끝난 뒤에도 "사진 4장 읽는 중"이 남는다. 완료형으로 바꿔야 한다.
7. 체크리스트의 "확인 필요"가 일반 문구다. 항목마다 이름 불일치, 편명 불일치 같은 이유를 보여 줘야 한다.
8. 큰 글씨 모드에서 헤더가 줄바꿈되고 입력 안내 문구가 잘린다. 보안 페이지에는 가+ 버튼이 없고, 채팅 고정 줄에는 원화가 없다.

## 4차 평가 후 반영 (2026-10-09, 로컬 테스트 통과 · 배포 대기)
1. 단정 표현: agent.md 예시를 "약관에서 보상하는 비용에 해당해요"로 바꿨다. coverage.md는 직원용 필드까지 확률 표현("보상 가능성 높음")을 금지한다.
2. 교차 청구: 에이전트 CONTEXT에서 다른 청구번호와 이름을 뺐다. 여행자에게는 "이 청구에는 쓸 수 없는 서류, 본인 명의로"만 전한다. 다른 청구·다른 사람을 언급하지 말라는 규칙과 테스트도 추가했다.
3. 웹 문구: 웹 채팅에는 "제출이라고 답하세요" 대신 제출 버튼을 안내한다(웹 전용 문구, 에이전트 규칙). 제출 문구에서 [CL-4]를 뺐다. 패킷 약관 표는 "플러스: 1일 한도 150 미국달러 · 여행당 한도 500 미국달러"처럼 줄 단위로 표시한다.
4. 제출 고정 줄: "추가 확인이 없으면 10/14(수)까지 지급"처럼 영업일로 계산한 날짜를 보여 준다. 확인이 필요한 건은 10영업일 안내로 바꿨다. 원화 금액을 함께 표시한다.
5. 확인 필요 사유: 항목별로 이름 불일치, 편명·날짜 불일치, 이 청구에 쓸 수 없음을 표시한다. 대시보드와 패킷에도 사유를 표시한다.
6. 진행 과정: 끝난 단계는 "사진 4장 읽음"으로 표시한다.
7. 패킷: 원래 항공권 항목에 "항공사 확인서로 확인 (예약번호·예정 출발 시각 기재)"을 표시한다.
8. 큰 글씨: 헤더를 한 줄로 유지한다(부제 말줄임, 전화 버튼은 아이콘만). 입력 안내 문구를 짧게 바꿨다. 보안 페이지에도 가+ 버튼을 넣었고, 채팅과 설정을 공유한다.
