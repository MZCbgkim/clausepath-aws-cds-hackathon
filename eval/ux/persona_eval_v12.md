## 12차 평가 후 반영 (2026-10-10, 배포·브라우저 QA 완료)

자격 증명을 갱신한 뒤 배포했다(알람 17개, FailedEvents 큐). 재부팅 뒤 데모를 다시 만들어 브라우저로 화면을 확인했다.

### 통제
- **금지 표현:**
  - 띄어쓰기를 허용한다: "보상 받으실 거예요", "환급 받으실 거예요", "지급 받으세요".
  - 새로 잡는 표현:
    - 금액 + 받으실 거예요
    - 보험금·금액 + 드릴게요, 송금해 드릴게요
    - "Your claim will be approved"
    - "This/that … is covered"
    - "qualify for / entitled to compensation"
  - 오탐을 고쳤다: "There is no guarantee", "Whether the hotel is covered…", 물음표로 끝나는 인용("환불돼요?"), "영수증에 금액이 나와요", "확인해 드릴게요".
  - 회귀 코퍼스: 걸러야 할 문구 75개, 통과해야 할 문구 31개.
- **인프라 알람(CDK 합성 기준 17개):**
  - 함수 5개마다 Errors(5분 5건 이상)와 Throttles 알람을 둔다.
  - HTTP API 5xx는 5분 10건 이상이면 울린다.
  - 비동기 함수 4개(inbound, email, disruption, reminders)는 두 번 재시도한 뒤에도 실패한 이벤트를 FailedEvents SQS에 14일 보관한다. 이 큐에 메시지가 1건이라도 있으면 알람이 울린다.
- **APPEAL_OVERDUE:** 대기열로 처음 넘길 때 한 번만 로그를 남긴다. 반복 알람이 없어졌고, 남은 기한 초과 건수는 KPI 잔량에서 본다.
- **KPI:** "발송 전 차단"과 "AI 응답 오류" 카드에 "발생일 기준"이라고 표시한다.

### 권한·검증
- **"처리 완료":** 인계받은 사람, 대기열에서 맡은 사람, 담당자, 관리자만 누를 수 있다. 서버는 403을 돌려주고 버튼은 비활성화된다.
- **남이 맡은 건 가져오기:** 사유가 있어야 한다. 서버는 409(takeover_needs_reason)를 돌려주고, 화면은 사유 입력 대화상자를 띄운다. 사유는 감사 기록에 남는다.
- **원결정 유지 회신:** 서버도 "확인한 내용:" 뒤의 실제 입력이 10자 이상인지 검사한다.
- **문자 제출 확인:**
  - YES는 단어 전체만 받는다. "y", "응", "확인"으로는 제출되지 않는다.
  - NO(아니요, 취소)를 보내면 취소된다.
  - 확인 문구에 취소 방법을 안내한다.

### 상담·심사
- **계좌 정정:** 본인 확인을 먼저 받는다. 그다음 대화상자에 멈출 계좌(은행, 끝자리, 예금주)와 고객에게 갈 문자 원문을 보여 준다.

  - 고른 시간대는 콜백에 저장해 다음 통화에서도 쓴다.
- **packet:** 상태 라벨 "승인"을 "지급 결정"으로 바꿨다.
